Context Compiler Explorer

When a chat with an AI gets too long, it has to be handed off to a fresh session. The usual way is a prose summary. This project instead compiles the chat into a small structured IR, using compiler ideas. Here is how the two compare.

Compile your own chat

Paste a transcript with lines starting User: and Assistant:, or choose a file: plain text, JSON messages, a chat-app data export, or JSON Lines. It is compiled by the Python pipeline on this computer.

The result

Does the IR lose context?

Smaller only counts if the new session can still answer questions about the chat. Each question below goes to a fresh session that has only the handoff. For the IR, that is the IR plus whatever the loader fetches for the question.

See every question

"Answerable" means the information needed for the answer is in what the new session receives. It does not test whether a model would then answer correctly. Questions were written from the expected-fact list, one per fact, plus one per abandoned or cancelled item.

How the compiler works

Four passes, each shown on this chat.

Pick out the decisions

Like a parser: pattern rules read each sentence and keep only settled facts.

A change becomes a new version, not an overwrite

Static Single Assignment (SSA): each version is written once, and the old one is kept in the history.

Phases of the chat become scopes

Like nested blocks in a program. Each fact belongs to the phase it was stated in. Phases still open at the end of the chat are the "active" ones.

Drop what is no longer reachable

Dead-code elimination: a fact survives only if its phase is still open, or it was mentioned again in an open phase. Every drop is logged with its reason.
